Olá! Preciso desenvolver um módulo complementar (estilo plugin/extensão) para o sistema ERP legado de um cliente. O sistema atual deles não possui funcionalidades para geração de etiquetas de produtos nem leitura de QR Codes para a gestão de materiais e manufatura.

Abaixo estão todos os detalhes, requisitos e o esquema do banco de dados para você me guiar na implementação da **Fase 1**.

---

### 1. Contexto & Arquitetura Geral
* **Objetivo:** Desenvolver uma aplicação web em **PHP** (utilizando o mesmo padrão/stack de projeto MVC/orientado a objetos previamente adotado em nosso sistema interno de chamados).
* **Banco de Dados:** Oracle Database 19c (será executado via container Docker localmente ou em ambiente AWS).
* **Escopo Atual (Fase 1):** 
  - Interface web para consulta e filtragem de materiais.
  - Geração e impressão de etiquetas físicas com QR Code associado a cada material.
  - Preparar a UI do Frontend com espaço/mockup para a leitura de QR Codes (que será integrada na Fase 2).
* **Escopo Futuro (Fase 2 - Manter arquitetura preparada):** 
  - Rotinas de movimentação física de estoque (entradas e saídas) acionadas por leitura do QR Code.

---

### 2. Regras de Negócio e Tabela de Materiais (`ESMATERI`)
A tabela principal do ERP é a `ESMATERI`.

* **Identificador Central:** A coluna `CD_MATERIAL` (VARCHAR2(20)) é a chave primária/identificador único do item. É essa informação que DEVE ser codificada no QR Code e exibida em destaque nas etiquetas.
* **Hierarquia dos Códigos:** O campo `CD_MATERIAL` inclui internamente a combinação do `CD_GRUPO` (3 caracteres) + `CD_SUB_GRUPO` (3 caracteres) + código sequencial do produto.
* **Colunas Relevantes:**
  - `CD_MATERIAL`: Código único do produto (base do QR Code/Etiqueta).
  - `DESCRICAO`: Descrição do material.
  - `CD_GRUPO` e `CD_SUB_GRUPO`: Utilizados para filtros e organização na interface.
  - `CD_UNIDADE_MEDI`: Unidade de medida (ex: UN, KG, M).
  - `LOCALIZACAO`: Endereço no estoque.
  - Colunas complementares de auditoria/consulta: `DT_CADASTRO`, `DT_MODIFICACAO`, `USUARIO_CRIACAO`, `USUARIO_MODIFIC`.

### 4. O que preciso que você crie/forneça agora:
1. **Estrutura de Arquivos Recomendada:** Organização limpa e modular do projeto PHP (separando conexão de banco, controllers, views e geradores de etiquetas).
2. **Conexão com Banco Oracle 19c:** Classe ou script PHP (PDO ou OCI8) configurado para conectar ao Oracle.
3. **Gerador de QR Code e Etiquetas:** Recomendação e exemplo de código com biblioteca PHP (ex: `endroid/qr-code`, `dompdf` ou `tcpdf`) para compor o layout da etiqueta impressa (contendo Descrição, Código do Produto, Localização e Imagem do QR Code baseado no `CD_MATERIAL`).
4. **Interface (Frontend):**
   - Tela com tabela para buscar e filtrar produtos (`CD_MATERIAL`, `DESCRICAO`, `CD_GRUPO`, `CD_SUB_GRUPO`).
   - Ação de acionar a visualização/impressão da etiqueta individual do item.
   - Componente visual (botão/modal desabilitado ou mockup) indicando o local para "Escanear QR Code", preparando para a Fase 2.
5. **Mocks de Teste:** Script SQL com comandos `INSERT` contendo dados fictícios válidos na tabela `ESMATERI` preenchendo os campos obrigatórios (NOT NULL) para que possamos testar localmente.
